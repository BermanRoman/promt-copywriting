# Локальный журнал текстового цикла

`scripts/loop.py` работает на Python 3.9+ со стандартной библиотекой.

Он хранит версии, отчёты и состояние допуска текста, но не вызывает модели, API или фоновые процессы и не выполняет фактчек самостоятельно.

Все команды запускаются из корня репозитория.

## Начало работы

Для написания сначала подготовьте первый черновик, затем создайте задачу.

Используйте временную папку вне репозитория либо заранее исключённую из Git папку `runs/`.

Инструмент сам не меняет `.gitignore`.

```sh
python3 scripts/loop.py init /tmp/article-loop --source /path/to/draft.md --profile written
python3 scripts/loop.py status /tmp/article-loop
```

Папка задачи не должна существовать: даже существующая пустая папка вызывает ошибку.

Исходник копируется побайтно в `text.md` и `snapshots/001.md`, исходный файл сохраняется.

Для `audit` параметр `--source` указывает на уже подготовленный результат аудита; исходный проверяемый текст остаётся отдельным контекстом, который инструмент не вкладывает в пакет.

| Профиль | Обязательные проверки |
| --- | --- |
| `simple` | `editorial`, `facts` |
| `written` | `editorial`, `facts`, `reader` |
| `video` | `editorial`, `facts`, `gusar`, `reader` |
| `audit` | `editorial` |

## Отчёты

Команда `status` выводит JSON с текущими `revision`, `text_hash`, состояниями проверок и вычисленным `status`.

Скопируйте `text_hash` в JSON отчёта отдельного рецензента.

```json
{
  "gate": "editorial",
  "text_hash": "ЗАМЕНИТЬ_НА_SHA256_ИЗ_STATUS",
  "reviewer": "editor-session-1",
  "verdict": "pass",
  "explanation": "Проверены структура, ясность и соответствие задаче.",
  "blockers": []
}
```

```sh
python3 scripts/loop.py review /tmp/article-loop /path/to/editorial-review.json
python3 scripts/loop.py review /tmp/article-loop /path/to/facts-review.json
```

Допустимы только шесть показанных полей, проверки своего профиля и вердикты `pass`, `revise`, `blocked`.

Строки должны быть непустыми, а `blockers` — списком непустых строк; для `pass` список обязан быть пустым.

Пояснение фактчекера может явно фиксировать отсутствие внешних проверяемых утверждений.

Инструмент проверяет форму пояснения, но не достоверность его содержания.

Новый отчёт той же проверки сохраняется отдельным файлом и заменяет её действующий вердикт на текущей версии.

`revise` или `blocked` сохраняют задачу неготовой, пока новый отчёт не снимет замечание либо новая версия не отзовёт все отчёты.

## Изменение текста и лимит

Редактируйте только рабочий `text.md`, затем явно зафиксируйте новую версию.

```sh
python3 scripts/loop.py advance /tmp/article-loop
# Эквивалентная команда:
python3 scripts/loop.py snapshot /tmp/article-loop
```

Новый SHA256 создаёт снимок и отзывает все прежние допуски, включая фактчек, редактуру и читателя.

Без изменения байтов команда не расходует версию.

До `advance` изменённый текст не принимает отчёты и не выдаётся читателю; `status` сразу теряет `ready`.

Лимит по умолчанию — три версии вместе с первым черновиком.

Последняя разрешённая версия может стать готовой после всех проверок; отрицательный вердикт на ней либо попытка дальнейшего изменения требуют решения автора (`needs_author`).

После исчерпания лимита инструмент не создаёт следующую версию и не повышает лимит самостоятельно.

Только по явному решению пользователя можно задать другой начальный лимит через `init --max-rounds N` или увеличить текущий с записью основания.

```sh
python3 scripts/loop.py extend /tmp/article-loop --max-rounds 4 --reason 'Автор разрешил ещё одну версию для уточнения фактов'
python3 scripts/loop.py advance /tmp/article-loop
# Либо остановить задачу:
python3 scripts/loop.py stop /tmp/article-loop --reason 'Требуется авторское решение по противоречивым источникам'
```

Остановленная задача остаётся в `needs_author` и не принимает новые отчёты или версии; продолжение оформляется новой задачей.

Сам инструмент не способен проверить полномочия человека, выполнившего `extend`.

## Читатель и Гусар

Читатель допускается после `editorial` и `facts` текущей версии, а для `video` также после `gusar`.

Гусар допускается после `facts`; его редактура меняет `text.md` и требует `advance`, затем нового фактчека и редакторской проверки.

Отчёт `gusar: pass` означает проверку окончательного текста, а не автоматический допуск за факт редактирования.

```sh
python3 scripts/loop.py reader-packet /tmp/article-loop --output /tmp/article-reader.md
python3 scripts/loop.py review /tmp/article-loop /path/to/reader-review.json
python3 scripts/loop.py status /tmp/article-loop
```

Пакет `/tmp/article-reader.md` содержит только точную копию текущего текста, без отчётов и редакторских инструкций.

Это верно только при правильном составе `text.md`: храните там видимый читателю материал, а источники для фактчека, отчёты и пояснения замысла — отдельно.

Инструмент не распознаёт и не удаляет служебные секции: для полного производственного сценария Motion сначала используйте сборщик зрительского пакета этого проекта.

Версия и SHA256 записываются снаружи видимого текста, в `/tmp/article-reader.md.json`.

Существующие выходные файлы не перезаписываются.

Отчёт читателя использует `gate: reader` и имя рецензента, отличное от последних имён редактора и Гусара этой версии, с игнорированием регистра и крайних пробелов.

Проверка имён не доказывает отдельного контекста: ведущий обязан сам передать пакет независимому читателю.

## Хранение и проверка

`state.json` заменяется атомарно; `snapshots/`, `reviews/` и `events/` пополняются без перезаписи записей.

Каждая новая команда загружает сохранённое состояние, поэтому перезапуск процесса не теряет допуски.

`ready` всегда вычисляется заново из SHA256 рабочего текста и действующих вердиктов, а не берётся из сохранённого флага.

Инструмент предполагает доверенное локальное хранилище: ручное изменение файлов журнала не является поддерживаемым интерфейсом.

Команды одной задачи сериализованы папкой `.lock`, но редактор текста этой блокировке не подчиняется: не редактируйте `text.md` параллельно с командой.

При аварийном завершении может остаться `.lock` или ещё не привязанный к состоянию снимок; остановите процессы и проверьте файлы вручную, инструмент не удаляет их автоматически.

Атомарность отдельного `state.json` не означает транзакцию сразу всех файлов и не гарантирует восстановление после повреждения диска.

Штатные ошибки путей, JSON и нарушений цикла возвращают код 2 с сообщением без traceback; успешная команда возвращает код 0 и JSON, в том числе при `needs_author`.

```sh
python3 -m unittest discover -s tests -v
```

Тесты проверяют отзыв допусков, устаревший hash, порядок проверок, имена рецензентов, чистоту пакета, лимит, сохранность исходника, повторное открытие состояния и схему отчётов.
